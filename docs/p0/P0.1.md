# P0.1 — Fundação técnica

Status: aprovada pelo usuário após teste interativo Windows em 27/11/2026. P00 aprovada pelo usuário em 27/11/2026.

## Escopo
Cliente Godot 4.7.2 Compatibility, Go 1.24+ (somente standard library), base PostgreSQL 16 e contrato JSON v1. Tela de prova local com conexão real, botão de reconexão e erro explícito. Não é a tela inicial final, não há gameplay, autenticação, multiplayer ou banco conectado. Porta 8090 exclusivamente loopback. O servidor valida bind local, expõe endpoints read-only e não aceita alteração de dados. Health informa database:not_connected.

## Executar
Windows: jogar.bat na raiz; requisitos Godot 4.7.2 e Go 1.24+ instalados uma vez. Nenhuma instalação automática. O launcher gerencia o processo próprio do servidor e deixa servidor externo intacto. Logs em build/. Linux:
```sh
cd server && go run ./cmd/colony
# em outro terminal, na raiz:
godot --headless --editor --import --path client
godot --path client
```

## PostgreSQL
Copie .env.example para .env e escolha uma senha local forte; execute docker compose up -d postgres apenas quando desejar preparar DB. A migration 001 é aplicada na inicialização de um volume vazio. Para volume existente, execute a migration via psql com credenciais locais; não apagar volumes existentes. O esquema estabelece contas por identidade de provedor, cinco slots únicos por conta e nome de personagem único sem distinção de caixa. Não armazena senha ou token. P0.2 definirá autenticação e P0.13 conectará persistência de gameplay; não afirmar que há persistência de jogo agora.
